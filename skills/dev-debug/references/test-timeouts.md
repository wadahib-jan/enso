# テストのタイムアウト診断と対処

テスト実行が制限時間を超えて終わらない場合のリファレンス。dev-debug のカテゴリ判定で「テストタイムアウト」に分類された場合に参照する。

テスト実行の速度そのものを改善するパターン集は [test-optimization-patterns.md](test-optimization-patterns.md) にある。**アプリケーション本体の性能問題はここでは扱わない**（本番のレスポンス劣化やメモリ使用量の問題は、テスト実行の問題とは原因も対処も別である）。

## 原因の6分類

| 分類 | 典型的な症状 | 見るべき箇所 |
|---|---|---|
| **非効率な処理** | データ量に比例して遅くなる | N+1 クエリ、不要なループ、大量データの逐次処理 |
| **外部 API のハング** | 特定のテストだけ制限時間まで無反応 | タイムアウト未設定の HTTP リクエスト、未応答のサービス |
| **デッドロック／無限ループ** | CPU を使い切る、または完全に停止する | 解決されない Promise、イベントループのブロック、再帰の終了条件欠如 |
| **大量テストデータ** | セットアップだけで時間を使い切る | 不必要に大きなテストデータセット |
| **セットアップ過重** | テスト数に比例して総時間が伸びる | `beforeAll` / `beforeEach` の重い初期化処理 |
| **リソースリーク** | 実行を重ねるほど遅くなる | 未クローズの接続・ストリーム・ファイルハンドル |

原因の切り分けは Explore サブエージェント（thoroughness: medium）に委ね、対象テストファイルとテスト対象の実装だけを読ませる。

## 分類ごとの修正方針

### 非効率な処理

- テスト範囲内で可能な最適化を行う
- テスト側で扱うデータ量を減らす
- 逐次処理をバッチ処理に変える

### 外部 API のハング

- モックを導入して実際の呼び出しを避ける
- テスト用の `AbortController` やタイムアウト設定を追加する
- テスト対象コード側にタイムアウト設定が不足している場合は、その事実を報告に残す

### デッドロック／無限ループ

- テストコード内の Promise 解決パターンを修正する
- ループの終了条件を修正する
- テスト用のタイムアウトガードを追加する

### 大量テストデータ

- 検証の本質を損なわない範囲でデータセットを削減する
- テストファクトリを最適化する

### セットアップ過重

- 不要な初期化を削除する
- テストごとに繰り返す必要のない処理を `beforeAll` に移す

### リソースリーク

- `afterAll` / `afterEach` でクリーンアップする
- 接続のクローズ処理を追加する

## 再実行による確認

修正後は明示的なタイムアウトを付けて実行し、結果を次のように扱う。

| 結果 | 判断 |
|---|---|
| タイムアウトせず成功 | 解消。完了とする |
| タイムアウトせず失敗 | タイムアウトは解消。残る失敗は別カテゴリとして dev-debug のフローに戻す |
| 再びタイムアウト | 前回と異なるアプローチで原因分析からやり直す |

## 最終手段: テストの分離

修正を重ねても解消できない場合に限り、そのテストを通常実行から分離する。

| ツール | 分離方法 |
|---|---|
| Jest | `describe.skip` + 専用設定ファイル（`jest.config.slow.js`）での実行 |
| Playwright | `@slow` タグを付けてフィルター実行 |
| pytest | `@pytest.mark.slow` マーカーを付与 |

分離したあとは通常のテスト実行でそのテストが除外されていることを確認する。

## ルール

- **テストを削除しない。** 分離は許容するが削除は許容しない
- **期待値を変更してタイムアウトを回避しない**
- 実装コードの本質的なロジックは変更しない（テスト通過のための最適化は除く）
- 分離した場合は、**そのテストの個別実行方法を必ず報告に記載する**（実行されないまま忘れられるのを防ぐため）
- テストを分離した箇所には、その理由をコメントとして残す
- 各リトライでは前回と異なるアプローチを試す

## 報告に残す項目

- 原因分類（上記6分類のどれか）と、そう判断した根拠
- 修正したファイルと変更内容、改善後の実行時間
- 分離した場合は、分離方法・個別実行コマンド・根本的な改善の方針
