# Task: dev-loop Step 10 の後始末ゲートを命令形にし正当なスキップと逸脱を区別する

## Goal

`skills/dev-loop/SKILL.md` の「Step 10: 後始末の確認」を命令形＋禁止形に改め、ゲート仕様表を追加する。
あわせて、Issue が「補足」で指摘した**正当なスキップ2条件**と**地の文で聞いてしまう逸脱**を、
定義上はっきり区別できる書き方にする。Issue が実際に発生したと報告しているのがこのゲートである。

## Interfaces

```markdown
### Step 10: 後始末の確認

**スキップしてよいのは次の2つだけである。**                          <!-- 🔵 既存のスキップ条件を限定列挙に変える -->
- `loop-state.yaml` の `status` が `failed`（中断した）
- `pr_number` が `null`（PR を作っていないローカル完結の構成）

**どちらにも該当しない場合、このゲートは AskUserQuestion で出さなければならない。** <!-- 🔵 案 A -->
**地の文で「マージしますか？」と書いて応答を終えてはならない。**                     <!-- 🔵 Issue の逸脱そのもの -->
**該当する場合は質問せず PR の URL を提示して終了する（聞くこと自体が逸脱）。**       <!-- 🟡 双方向の明示は新規 -->

| 項目 | 内容 |
|---|---|
| question | マージして後始末しますか？                          <!-- 🟡 文言は新規 -->
| header   | 後始末                                              <!-- 🟡 新規 -->
| 選択肢1  | はい — マージして後始末する → `dev-cleanup` を起動   <!-- 🔵 既存の表を移送 -->
| 選択肢2  | いいえ — PR は残す → PR の URL を提示して終了        <!-- 🔵 既存の表を移送 -->
```

## Test Strategy

- [ ] Step 10 に「AskUserQuestion で出さなければならない」旨の**命令形**が含まれる
- [ ] 同じ箇所に「地の文で確認して終了してはならない」旨の**禁止形**が含まれる
- [ ] 正当なスキップ条件が `status: failed` と `pr_number: null` の**2つに限定**されていることが読み取れる
- [ ] 「スキップ条件に該当するなら聞かない／該当しないなら必ず選択式で聞く」の両方向が書かれている
- [ ] ゲート仕様表に question / header / 選択肢2件 とその動作がすべて記載されている
- [ ] 既存の分岐（はい→`dev-cleanup` 起動 / いいえ→URL 提示して終了）が変更されていない
- [ ] 「いいえ」でも `status` が `shipped` のままである旨の既存記述が残っている
- [ ] 「`dev-cleanup` をサブエージェント経由で起動しない」の既存注意書きが残っている
- [ ] 「ルール・制約」節に承認ゲートを AskUserQuestion で出す旨の1行が追加されている
- [ ] エッジケース: `status: failed` かつ `pr_number: null` の両方に該当する場合もスキップ（矛盾する指示にならない）
- [ ] エッジケース: 変更後も `skills/dev-loop/SKILL.md` が 500 行以内である

## Implementation Notes

- 参照すべき既存コード:
  - `skills/dev-cleanup/SKILL.md` Step 3 — 禁止形の手本
  - `skills/dev-loop/SKILL.md` の「状態ファイル仕様」表 — `status` の取りうる値の定義。ここと矛盾させない
- 実装のヒント: 現状の「次の場合はこのステップを飛ばし〜」という条件文を、
  **限定列挙（この2つだけ）** と読める形に直すのが要点。
  「聞かずに終わる正当な経路がある」ことが、地の文で聞いて終わる逸脱の言い訳にならないようにする
- 注意事項: このゲートは `dev-cleanup` の Step 3 ゲートに繋がる。
  「はい」を選ぶと `dev-cleanup` 側でもう一度マージ確認が出る構成は既存のまま変えない
- 変更は記述のみ。hooks は触らない（Issue の案 C は不採用）
