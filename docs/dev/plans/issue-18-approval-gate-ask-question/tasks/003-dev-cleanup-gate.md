# Task: dev-cleanup Step 3 のゲート記述を仕様表の形式に揃える

## Goal

`skills/dev-cleanup/SKILL.md` の「Step 3: 確認（唯一のゲート）」に、001 / 002 と同じ
ゲート仕様表（question / header / 選択肢と動作）を追加し、3つの承認ゲートの記述形式を揃える。
禁止形は既に存在するため、案 A の追加作業はほぼ不要で、本タスクは案 B（仕様の明文化）が主となる。

## Interfaces

```markdown
### Step 3: 確認（唯一のゲート）

AskUserQuestion で確認する。**このステップを飛ばしてはならない。**  <!-- 🔵 既存。変更しない -->
**地の文で確認して応答を終えてはならない。**                        <!-- 🟡 001/002 と揃えるための追記 -->

| 項目 | 内容 |
|---|---|
| question | マージして後始末しますか？                    <!-- 🟡 文言は新規 -->
| header   | マージ確認                                    <!-- 🟡 新規 -->
| 選択肢1  | はい — マージして後始末する → Step 4 へ       <!-- 🔵 既存の表を移送 -->
| 選択肢2  | いいえ — 何もしない → 何もせず終了する        <!-- 🔵 既存の表を移送 -->
```

## Test Strategy

- [ ] 既存の「**このステップを飛ばしてはならない。**」がそのまま残っている
- [ ] 地の文で終えてはならない旨の禁止形が追記されている
- [ ] ゲート仕様表に question / header / 選択肢2件 とその動作が記載されている
- [ ] 既存の分岐（はい→Step 4 / いいえ→何もせず終了）が変更されていない
- [ ] 提示内容の既存リスト（PR 番号・URL、`mergeStateStatus` と CI 詳細、`mergeMethod`、削除対象）が残っている
- [ ] エッジケース: CI 詳細を取得できなかった場合も「明示したうえで Step 3 に進む」既存の扱いが変わっていない
- [ ] エッジケース: 変更後も `skills/dev-cleanup/SKILL.md` が 500 行以内である
- [ ] `pnpm secretlint && pnpm check` が通る

## Implementation Notes

- 参照すべき既存コード: `skills/dev-cleanup/SKILL.md` の「### Step 3: 確認（唯一のゲート）」
- 実装のヒント: このゲートは**既に一番強い書き方をしている**。壊さないことが最優先で、
  足すのは仕様表と、001 / 002 と同じ禁止形の1文だけにとどめる
- 注意事項: Issue はこのファイルを「マージ前の確認を持つ場合は同様の扱いが要る」として条件付きで挙げている。
  実際に確認を持っているため対象に含めたが、**振る舞いの変更は行わない**
