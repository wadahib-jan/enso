# Plan: issue-18-approval-gate-ask-question

## Requirements Summary

Issue [#18](https://github.com/yukimnb/enso/issues/18)（enhancement）の解消がゴール。

承認ゲート（`dev-plan` Phase 5e / `dev-loop` Step 10）は AskUserQuestion による選択式と定められているが、
実際には地の文（通常の応答テキスト）で「〜しますか？」と聞いて終了する逸脱が発生する。
選択肢が UI に出ないため承認の意思表示が曖昧になり、「はい」に紐づく後続スキルの起動という定義された分岐が働かず、
ゲートを通過したかどうかも後から追えない。

Issue が推奨する **案 A（記述を命令形＋禁止形に統一）＋ 案 B（ゲート仕様を表で定義）** を採用する。
案 C（hooks による検出）は Issue 自身が「状態の判定が難しく誤検知しやすい／現時点では過剰」と評価しているため採用しない。

**スコープ外（意図的）**: Issue の「影響範囲」に **要検討** として挙がっている
`enso-issue-fix` Step 0b / 1b、`enso-issue-report` Step 1 / 4 / 5 の書き方統一は本 Plan に含めない。
これらは承認ゲート（外向きで取り消しにくい操作の直前に置かれた判断点）ではなく、
入力を集めるための選択プロンプトであり、性質が異なる。Issue 側でも確定した要望になっていない。

## Design Overview

### 調査で分かった現状

| 箇所 | 現状の記述 | 問題 |
|---|---|---|
| `skills/dev-plan/SKILL.md` 5e（323行目付近） | 「そのうえで AskUserQuestion で確認する。」＋選択肢2行の表 | 平叙形のみ。禁止形なし。ルール・制約にも記載なし |
| `skills/dev-loop/SKILL.md` Step 10（159行目付近） | 「該当しなければ AskUserQuestion で確認する。」＋選択肢2行の表 | 同上。正当なスキップ条件と逸脱の区別が読み取りにくい |
| `skills/dev-cleanup/SKILL.md` Step 3（107行目付近） | 「AskUserQuestion で確認する。**このステップを飛ばしてはならない。**」 | **既に禁止形を持つ唯一のゲート。これが手本になる** |

つまり本 Issue の実体は「3つある承認ゲートのうち、`dev-cleanup` だけが強い書き方をしていて、
`dev-plan` / `dev-loop` が追随していない」という記述の不揃いである。

### 設計方針

1. **案 A**: `dev-cleanup` Step 3 の書き方（禁止形の併記）を基準に、`dev-plan` 5e と `dev-loop` Step 10 を揃える。
   さらに各スキルの「ルール・制約」節にも1行を置き、SKILL.md の末尾だけを読んでも制約が拾えるようにする。
2. **案 B**: ゲート仕様（**質問文・選択肢のラベル・各選択肢の動作**）を、**各ゲートの現地に表として埋める**。
   スキルは1つずつ独立して読み込まれるため、共有の一覧表を別ファイルに置いても実行時には参照されない。
   人間向けの俯瞰用一覧のみ `MANUAL.md` に置く。
3. **正当なスキップとの区別**（Issue「補足」への対応）: `dev-loop` Step 10 には
   `status: failed` と `pr_number: null` という正当なスキップ条件がある。
   「**スキップ条件に該当するなら質問せず終了してよい。該当するのに聞くのも、該当しないのに地の文で聞くのも逸脱**」と
   両方向を明示し、「聞かずに終わる」経路と「地の文で聞いて終わる」逸脱を混同させない。

### 変更しないもの

- hooks（案 C 不採用のため `hooks/` は一切触らない）
- 選択肢の意味・分岐先（`dev-loop` / `dev-cleanup` の起動条件）— 既存の挙動を変えず、記述の強度と具体度だけを上げる
- `.claude-plugin/plugin.json`（ディレクトリ単位の指定のため変更不要）
