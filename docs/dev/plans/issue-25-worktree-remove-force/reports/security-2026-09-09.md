### 検査した観点

#### 1. OS コマンドインジェクション（SWS 1.2 / CWE-78）

> 出典: 安全なウェブサイトの作り方 改訂第7版「1.2 OS コマンド・インジェクション」p.13-15
> https://www.ipa.go.jp/security/vuln/websecurity/about.html

本変更で追加したコマンド実行箇所:

| 箇所 | 実行内容 | 評価 |
|---|---|---|
| `remove_worktree()` | `run git -C "$MAIN" worktree remove --force "$wt"` | 変数はすべて引用符付きで**引数として**渡している。シェル解釈を経由しない |
| 同上 | `git -C "$MAIN" worktree list --porcelain \| grep -qxF "worktree $wt"` | `grep -F`（固定文字列）+ `-x`（行全体一致）。`$wt` を正規表現として解釈しない |
| 同上 | `run git -C "$MAIN" worktree prune` | 変数展開なし |
| 同上 | `run rm -rf "$wt"` | 引用符付き。下記 2 を参照 |

`eval` / `sh -c` / バッククォートによる再解釈は追加していない。既存の `run()` は `"$@"` で引数配列をそのまま実行する形であり、文字列連結によるコマンド組み立ては行われていない（根本的解決の 1: シェルを経由しない関数の利用に相当）。

`$wt` の供給元は `git worktree list --porcelain` の出力（`worktree_of()` の awk 抽出）であり、ローカルの git 管理情報に由来する。外部入力ではない。

#### 2. パスの取り扱い（SWS 1.3 ディレクトリトラバーサル / CWE-22 の考え方を援用）

> 出典: 安全なウェブサイトの作り方 改訂第7版「1.3 パス名パラメータの未チェック / ディレクトリ・トラバーサル」p.16-19

`rm -rf` は本スクリプトで唯一の非可逆な直接削除であるため、実行前に次の 2 条件を課している。

```bash
if [[ "$wt" != "$MAIN/.claude/worktrees/"* ]]; then
  echo "    ⚠ $wt は $MAIN/.claude/worktrees/ の外にあるため回収しません。..." >&2
  return 1
fi
```

- **削除対象を固定のベースディレクトリ配下に限定**している（根本的解決の 1: 外部からのパス指定を避ける、および 2: パスが想定内かを確認する、に相当）
- ベースは `$MAIN`（`git worktree list` の先頭エントリ = 本体チェックアウトの絶対パス）から組み立てており、相対パスの解決に依存しない
- この分岐に到達するのは `git worktree remove --force` が失敗し、**かつ**管理エントリが既に消えている場合のみ。通常経路では実行されない

残る限界（受容する）:

- `$wt` に `..` を含む文字列が入れば前方一致を満たしたまま外に出られる。ただし `$wt` は git が管理する worktree の**正規化済み絶対パス**であり、`..` を含んだ形では出力されない。攻撃者が任意の値を注入できる経路は存在しない（`git worktree list` の出力を書き換えられる者は、そもそもリポジトリに対する任意の書き込み権限を持つ）
- シンボリックリンクだった場合、`rm -rf` はリンク自体を削除し、リンク先の実体は削除しない
