## Coding Conventions

### 読み込みの仕組み（最重要）

Claude Code がプラグインを探索するのは `.claude/skills/*` のみ。`.claude-plugin/plugin.json` の `skills` が指すディレクトリが登録され、`/enso:` プレフィックス付きで使えるようになる。

- `skills/` は**直下1階層のみ。ネストしたディレクトリは読み込まれない** 🔵（スキル内部の `references/` のような分割は問題ない）
- enso は**スキルのみで構成される**。`commands/` は持たない 🔵
- `plugin.json` はディレクトリ単位の指定なので、スキルを増減してもマニフェスト変更は不要
- `hooks/hooks.json` はマニフェストに書かなくても自動検出される。スクリプトは `${CLAUDE_PLUGIN_ROOT}` で参照する

### ファイル形式

**スキル（`skills/*/SKILL.md`）**: frontmatter は `name` / `description` /（任意で）`argument-hint`。`description` は `This skill should be used when the user asks to "xxx", "日本語トリガー", ...` の形式でトリガーワードを列挙し、続けて日本語で機能説明を書く。本文は `## 前提知識` → `## ワークフロー` → `## ルール・制約` → `## 追加リソース` の構成。

### 言語

ドキュメント・スキル定義・コミットメッセージはすべて**日本語**。コード内の識別子は英語。

### 信号機システム

多くのスキルが確信度を明示する共通規約を持つ:

- 🔵 **前工程指示** — 設定ファイルや明示的な仕様から直接読み取れた
- 🟡 **妥当な推測** — ベストプラクティスに基づくが明示的な前例がない
- 🔴 **AI推論補完** — アーキテクチャ判断や組織固有ポリシーに依存する

### hooks を書くときの原則

- **`jq` に依存しない。** stdin の JSON は Node でパースする（Biome の lint 対象になる）
- **必ず exit 0 で終える。** `runHook()` が例外を握り潰す。hook のバグでセッションが止まるのが最悪のシナリオ
- **内容の基準は `git rev-parse --show-toplevel`**（`gitState().topLevel`）。設定ファイルの位置ではない。worktree 内では両者がずれる

### Bash の扱い

スキル内の Bash コマンドはプロジェクトルートの**絶対パス**を使う。worktree セッション中はコマンド置換（`$(...)`）で組み立てず、確定済みの絶対パスを直接書く。

## Additional Notes

- **投入は全プロジェクトに即座に効く。** user スコープに置くため、壊れた状態を投入すると全プロジェクトのセッションに影響する。`install-local.sh` は `--delete` 付きなので、リポジトリ側から消したスキルは投入先からも消える（ディレクトリごと消えた場合も `install-local.sh` が投入先から削除する）。**投入前に必ず品質ゲートを通すこと** 🔵
- **コピー方式なので、リポジトリを編集しただけでは反映されない。** 反映には投入 ＋ Claude Code の再起動（または `/reload-plugins`）が必要
- **hooks はセッション開始時に読み込まれる。** 編集後は投入に加えて再起動が必須
- **強制モードは設定があるプロジェクトでのみ動く。** `<project>/.claude/enso.json` に `enforce.enabled: true` が無ければ全 hook が無出力で exit 0 する（＝挙動が一切変わらない）
- ブランチ戦略: `main`（安定版）/ `feature/機能名` / `bugfix/バグ名`
- コミットメッセージは [Conventional Commits](https://www.conventionalcommits.org/) 形式（`feat:` / `fix:` / `docs:` / `refactor:` / `test:` / `chore:`）
- 🟡 このリポジトリは case-insensitive なファイルシステム上にあり、git がルートを `/workspace/Enso`、セッションが `/workspace/enso` と認識する。そのため `EnterWorktree` によるセッション切り替えは失敗する（worktree 自体は `git worktree add` で作成し、パスを直接指定すれば使える）
